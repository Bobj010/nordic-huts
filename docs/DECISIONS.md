## ADR-001: Использование SQLite в качестве базы данных по умолчанию
* **Дата:** 2026-11-15
* **Статус:** Принято
* **Контекст:** Проект является индивидуальной учебной работой и должен безупречно разворачиваться на компьютере преподавателя без необходимости устанавливать локальный сервер MySQL/PostgreSQL или вспоминать учетные данные root.
* **Решение:** Использовать SQLite (файл `database/database.sqlite`). Все миграции пишутся строго по стандарту Laravel без платформозависимых хаков, поэтому переключение на MySQL в `.env` занимает ровно 10 секунд.
* **Последствия:** Мгновенный старт проекта (`php artisan migrate --seed`), нулевые внешние зависимости для проверяющего.

## ADR-002: Серверный рендеринг (Blade) + Tailwind CSS v4 вместо SPA (React/Vue)
* **Дата:** 2026-11-15
* **Статус:** Принято
* **Контекст:** Для сдачи преподавателю важно показать владение Blade-шаблонами, директивами `@auth`, `@guest`, `@forelse` и серверными сессиями. SPA (Inertia/React) добавило бы оверинжиниринг в сборку, дублирование роутинга и усложнило бы защиту кода.
* **Решение:** Чистые Blade-шаблоны + современный Tailwind CSS v4 (через Vite) + Alpine.js для микро-интерактивности (модальные окна, выпадающие списки).
* **Последствия:** Быстрая загрузка, легкая для понимания структура представлений, высокая скорость рендера.

## ADR-003: Промежуточная таблица `house_amenity` (Связь Many-to-Many)
* **Дата:** 2026-11-15
* **Статус:** Принято
* **Контекст:** В требованиях к индивидуальным проектам приветствуется демонстрация различных типов реляционных связей. Простой блог обычно ограничен только связью `One-to-Many` (Category -> News).
* **Решение:** Вынести удобства в отдельную модель `Amenity` и связать с домиками через `house_amenity` (`belongsToMany`).
* **Последствия:** Проект демонстрирует красивую нормализованную БД (3NF) и работу с методами `$house->amenities()->sync($ids)` при сохранении формы в админке.

## ADR-004: Фирменный эндпоинт `/quick-login/{role}` для защиты проекта
* **Дата:** 2026-11-15
* **Статус:** Принято
* **Контекст:** На защите у студента есть от 3 до 7 минут, чтобы показать функционал всех 4 ролей. Ввод логинов и паролей вручную отнимает драгоценное время и повышает вероятность опечатки.
* **Решение:** Внедрить безопасный служебный роут `/quick-login/{role}`, который доступен через аккуратные кнопки в шапке сайта (`Гость`, `Клиент`, `Менеджер`, `Админ`) и мгновенно авторизует под нужным аккаунтом.
* **Последствия:** Демонстрация сценариев за 60 секунд без единой заминки.
